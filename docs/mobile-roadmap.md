# Мобильное приложение и развитие

## Что готово сейчас

Адаптивный сайт, приватные диалоги с опросом новых сообщений, контакты по согласию,
API `/api/v1/`, JWT с ротацией и отзывом refresh, пагинация и OpenAPI.
Сайт работает в мобильном браузере. Установочного Android/iOS-приложения пока нет.

## Рекомендуемая последовательность

1. Подтверждение университетского email, правила модерации, жалобы, блокировки пользователей.
2. WebSocket-события для диалогов и уведомления о новых откликах.
3. PWA: иконки, manifest и установка на домашний экран. Приватные API-ответы
   не кэшировать service worker по умолчанию.
4. Мобильный клиент: Flutter или React Native после выбора требований и платформ.
   Использовать OpenAPI как контракт и генерировать типы клиента.
5. Хранить токены в Keychain/Keystore, refresh обновлять централизованно,
   очищать при выходе; для веб-клиента продолжать использовать HttpOnly-сессии.
6. FCM/APNs для push, настройки уведомлений и управление токенами устройств.

## Звонки

Сейчас ссылка `tel:` открывает стандартное приложение телефона; браузер/ОС
запрашивает дальнейшее действие. Номер публикуется только по согласию продавца.
На компьютере требуется приложение, способное обработать `tel:`.

Звонок через интернет внутри приложения — отдельная функция: WebRTC,
сигнализация, STUN/TURN, разрешение микрофона, обработка входящих вызовов и блокировки.
Не стоит включать её в первую версию ВКР до стабилизации переписки и модерации.

## Дополнительные функции по приоритету

- Жалобы, очередь модерации, блокировка отправителей, аудит решений.
- Подтверждение университетского email (интеграция с SSO — при доступе университета).
- Уведомления об ответе, подборки по сохранённому поиску.
- Состояние «продано», история изменения цены, отметка о завершении взаимодействия.
- Сохранённые фильтры, похожие объявления, PostgreSQL-поиск с ранжированием.
- Несколько кампусов/общежитий, карта места встречи без публикации домашнего адреса.
- Несколько устройств, просмотр и отзыв активных сессий.

Каждая функция получает отдельные модели/миграции, API-контракт, проверки доступа
и пользовательский сценарий. Платежи, доставка и верификация документов в текущий объём не входят.
