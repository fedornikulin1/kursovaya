# Доступ, модерация и поддержка

## Студенческие аккаунты

`STUDENT_ACCESS_ONLY=true` закрывает самостоятельную регистрацию на сайте и в API.
Публичный каталог можно просматривать без аккаунта. Для входа и публикации
администратор создаёт обычную учётную запись, сверяет студенческий статус и применяет
действие «Подтвердить статус студента» в разделе пользователей. Для приглашения
можно задать случайный пароль и предложить установить свой через штатное восстановление
после настройки SMTP. Суперадминистратор входит для управления площадкой.

Интеграция с СВФУ требует согласованной регистрации приложения в системе единого
входа университета. Запросите доступный протокол (OpenID Connect или SAML),
тестовую среду, требования к адресу возврата и атрибут активного студента.
Пароль вводится на стороне университета. После согласования нужно привязывать
аккаунт по стабильному идентификатору, проверять статус при входе и согласовать
отзыв доступа после выпуска или отчисления.

## Антиспам и DDoS

Лимиты действуют на попытки одного аккаунта в пределах временного окна.

| Операция | Лимит |
| --- | --- |
| Чат кампуса, включая комнаты | 12 отправок в минуту, до 1 000 символов в сообщении и 16 КБ на запрос |
| Новые объявления и учебные запросы | 8 попыток в час суммарно через сайт и API |
| Изменения объявлений и загрузка дополнительных фото через API | 30 попыток в минуту |
| Личные сообщения | 30 отправок в минуту, до 4 000 символов в сообщении |
| Обращения и жалобы | 8 попыток создания в час |
| ИИ-помощник | 5 попыток в минуту на аккаунт, до 30 обращений к провайдеру в минуту на площадку |

Сервер отвечает `429` с `Retry-After` при исчерпании лимита и `413` при
превышении размера запроса на коротких формах. Для нескольких процессов Django
задайте общий `CACHE_URL` на Redis. При пустом адресе у каждого процесса свой счётчик.

Для публичного размещения поставьте Cloudflare или аналогичную защиту перед
хостингом и ограничьте прямой доступ к серверу со стороны интернета. На прокси
ограничьте частоту запросов к входу, чату и формам записи. Ограничьте размер запросов
до попадания в Django: для чата до 16 КБ, для публикации с фото нужен отдельный
лимит с учётом до восьми изображений по 5 МБ. Учитывайте, что жители общежития могут
выходить в сеть с одного IP.

## Работа модератора

Откройте «Участники и доступ» → «Пользователи». С карточки пользователя можно
перейти к его объявлениям и сообщениям в чате кампуса при наличии соответствующих
прав. Личные диалоги доступны суперадминистратору после выбора диалога и указания
причины. Кто, когда и зачем открыл переписку, видно в истории пользователя.
Используйте этот доступ для разбора конкретного обращения.

Действие «Заблокировать аккаунты» отключает вход, отзывает токены обновления и
скрывает объявления аккаунта из каталога. Действие «Снять блокировку аккаунтов»
восстанавливает доступ при наличии допуска. Для окончательного удаления откройте
карточку пользователя и проверьте список связанных записей на экране подтверждения.
Ранее опубликованные сообщения общего чата можно удалить отдельно через список
сообщений пользователя.

Чат и опубликованные объявления проверяются серверными правилами. Объявления
проверяются при создании, изменении и публикации из админки. При спорном случае
модератор может архивировать объявление, удалить сообщение чата или заблокировать
аккаунт. Правила работают по тексту. Фото и неоднозначные формулировки проверяет
модератор по обращениям.

## Помощник

Укажите в окружении сервера `SUPPORT_AI_API_KEY` и `SUPPORT_AI_MODEL_URI` (URI
модели Yandex AI Studio с идентификатором каталога). После перезапуска в центре
помощи появится «Спросить ИИ-помощника». Для ответа передаются введённый вопрос
и опубликованные записи FAQ. Вопрос ограничен 600 символами. Если сервис
недоступен, пользователь может открыть обращение к сотруднику.

- [Получение ключа AI Studio](https://yandex.cloud/ru/docs/iam/concepts/authorization/api-key)
- [Отключение логирования запросов AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging)

Для локальных автоматических тестов в PowerShell с включённым закрытым режимом
временно задайте `$env:STUDENT_ACCESS_ONLY = 'false'` в окне запуска тестов.
Отдельные тесты сами включают закрытый режим для проверки допуска.
